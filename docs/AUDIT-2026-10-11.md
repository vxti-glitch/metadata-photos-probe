## MP4 processing failure

The native importer marks its staged originals read-only (`0400`). The movie writer copied that file and inherited its permissions, then opened the copy for modification. The writer now makes only its new output writable (`0600`). Original/provider bytes and source permissions remain unchanged. Regression coverage includes playable MP4/MOV processing from read-only originals and a hosted iOS import → processMetadata roundtrip.

This is a concrete defect matching the reported broad failure pattern. The exact attached screenshot cannot identify its underlying error because the previous bridge discarded the failure category. The user's original failing videos and installed build were not available for reproduction.

## Other confirmed fixes

| Area | Fix |
| --- | --- |
| Video parsing | Handle extended-size `ftyp`, inspect the complete bounded brand list, refuse oversized or malformed brand lists before allocation, and derive parsing bounds from the opened file rather than cached URL file-size information. |
| Video metadata | Preserve non-`mdta` namespaces; reject duplicate/conflicting editable metadata containers or values; verify targeted values/removals per video track. Missing evidence stays incomplete. |
| Location | Refuse partial coordinate removal that would silently remove another coordinate or altitude. Opaque legacy location records require an explicit action on all tuple components. |
| Cancellation | Propagate cancellation through the encoded-sample verifier instead of converting it into an incomplete, potentially exportable result. |
| Image metadata | Refuse full EXIF edits with unqualified SubIFD pointers that can alias retained values. Refuse retired-Exif scrubbing inside HEIC `meta/idat`, where rewriting the parent box would restore the removed bytes. |
| PNG qualification | Keep opaque EXIF/TIFF preservation incomplete after an edit. Exact unchanged complete files can still be verified by their byte hashes. |
| Publication/export | Publish only fully verified outputs after durable session commit. Use separate public copies, retain existing files on collisions, and report automatic saving only after success. Incomplete results require acknowledgment and explicit export. |
| Editor state | Disable stale editing/export controls when post-cancellation reconciliation fails. Gate preset reset and report persistence failures with rollback. |
| Dates | Preserve the represented instant and original ISO offset when staggering batch timestamps, including offsets, UTC and day rollover. |
| Presets | Align native and Dart name limits at 128 UTF-8 bytes. Reject a serialized export above the 32 KiB import limit without replacing the last valid preset. |
| Diagnostics | Distinguish unsupported, malformed, readback, integrity, storage and processing errors. Expose safe framework codes instead of resource descriptions or paths. Generic failures no longer imply a camera-profile conflict. |
| Native/UI integration | Release the operation gate when the location picker is dismissed. Stop inventing a researched profile for unknown hardware. Remove false permission, readiness, automatic-save and network claims. |
| Build/performance | Check formatting without modifying the source being built; run editor CI for all script changes. Skip redundant media-payload hashing during structural inspection; encoded integrity checks still run. No performance benchmark claim is made. |
